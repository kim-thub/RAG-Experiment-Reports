# 실험 보고서 작성 기준

이 저장소의 보고서는 실험 결과를 다시 해석할 수 있게 측정 대상, 입력 범위, 비교 조건, 근거와 한계를 함께 기록합니다. 보고서는 구현 완료나 운영 적합성의 승인을 대신하지 않습니다.

## 보고서에 기록할 항목

1. **질문과 목적:** 어떤 가설이나 선택을 확인하려는지 한 문장으로 적습니다.
2. **측정 대상:** 검색 근거 회수, 생성 답변의 사실성, 지연 시간처럼 실제 측정한 대상을 구분합니다. 검색 지표만으로 답변 품질을 주장하지 않습니다.
3. **자료와 라벨:** 데이터 출처, 문서·질문 수, 정답 라벨의 검수 상태, 제외 기준을 기록합니다. 권리 조건은 [데이터 출처 문서](../DATA_SOURCES.md)에 연결합니다.
4. **비교 조건:** 기준선과 후보 방법의 코드 버전, 모델·임베딩, 주요 설정, 실행 범위를 기록합니다. 조건이 같지 않으면 표와 해석에서 차이를 밝힙니다.
5. **지표와 결과:** 지표 정의, 분모, 누락값, 결과 단위를 명시합니다. 제공받은 값, 복원된 기록, 직접 재실행한 값을 서로 구분합니다.
6. **한계와 실패:** 작은 표본, 부분 입력, 불완전 라벨, 생성 오류와 인용 검증 범위를 기록하고 확인하지 않은 결론은 유보합니다.
7. **재현 범위:** 코드 복원, 합성 입력 회귀 확인, 부분 재실행, 전체 실험 재실행 중 실제로 수행한 수준만 표시합니다.
8. **결정:** 운영 적용·기본값 변경 여부는 결과와 별도 항목으로 두고, 보류나 추가 검증이 필요한 이유를 씁니다.

## 결과를 공개할 때

- 실행 기록이나 원본 파일에서 확인되지 않은 설정·수치·설명을 추정해 채우지 않습니다.
- 서로 다른 자료 범위나 실행 조건을 하나의 점수처럼 합치지 않습니다.
- 표본이 작거나 정답 라벨이 검수 중이면 이를 결과 제목과 해석에 드러냅니다.
- 질문 전문, 원본 청크, 실제 모델 입력·응답, 자격정보, DB URL, 비공개 추적은 보고서에 복사하지 않습니다. 필요한 경우 저장소 밖의 승인된 비공개 위치에서 관리합니다.
- 재실행은 입력 자료, 권리, 비용, DB 대상이 확인되고 명시적으로 승인된 경우에만 진행합니다.
