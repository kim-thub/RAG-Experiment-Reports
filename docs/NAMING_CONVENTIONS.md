# 코드 및 실험 네이밍 규칙

- Python 파일·함수·변수·모듈은 PEP 8 `snake_case`를 사용한다. 모듈 파일명에 하이픈을 쓰지 않는다.
- 클래스·Protocol·예외 타입은 `PascalCase`를 사용한다.
- 상수는 `UPPER_SNAKE_CASE`를 사용한다.
- 테스트는 `tests/test_rag_<subject>.py` 형식을 우선한다. 공유 fixture는 `tests/rag_test_fixtures.py`에 둔다.
- 설정 환경변수는 `RAG_` 접두사를 사용한다. LLM 서비스의 환경변수 이름을 재사용하지 않는다.
- 데이터베이스 schema·table·column 이름은 `snake_case`를 사용한다. 스키마 변경은 승인 전에 만들지 않는다.

## 실험 보고서 표기

- 한 보고서 안에서 비교군 ID를 한 번 정의하고 모든 표·본문·부록 참조에서 같은 ID를 사용한다.
- 비교군 ID와 지표의 의미를 보고서 안에 함께 적는다. ID만 보고 알고리즘이나 실행 조건을 추측하게 두지 않는다.
- Hit@k, Recall@k, MRR@k 등은 실제 계산 기준과 k 값을 분명히 표기한다. 같은 이름의 지표라도 분모나 정답 라벨 기준이 다르면 별도로 설명한다.
- 코드 복원, 합성 fixture 회귀 확인, 부분 실험, 전체 실험 재실행을 서로 다른 상태로 기록한다.
- G1은 기존 Ollama 경량 그래프 실험에만 사용한다. Microsoft GraphRAG Local/Global 래퍼는 별도 방법으로 표기한다.
